# R4 엔지니어링·성능·유지보수 좌석

측정(localhost:5188 ko, 375px 모바일 에뮬레이션 포함): DOM 1,557개, 스크립트 23, CSS 13+폰트 CSS, 요청 96건(첫 로드), DCL 131ms/load 184ms(로컬), JS 힙 약 20MB, 카드 20~21장, 가로 스크롤 없음, 비교 버튼(#cmpBtn)과 `<dialog>` 비교창 구현 확인. site.js 61KB, i18n.js 55KB, style.css 57KB, 전체 JS+CSS 약 533KB(빌드 없음).

## 1) 결론
Part 1과 비교 트레이는 "싸게" 잘 들어갔다(새 의존성 0, dialog 네이티브, 새 호스트 0). 이제 남은 일은 기능 추가가 아니라 (a) 모바일 44px 잔여 누락 정리, (b) 가격/환율 표기 정직성, (c) 중복 코드·죽은 CSS 삭제다. 다크모드는 만들지 말 것(현재 사이트는 prefers-color-scheme 규칙 0개, 내 브라우저는 dark인데 배경 rgb(238,241,238) 단일 라이트 테마라 일관됨. 반쪽 다크가 가장 나쁜 결과). 시간 단위 환율은 불필요.

## 3) 신규 제안 TOP 5
1. [S] `<meta name="color-scheme" content="light">` + dialog(::backdrop 포함) 라이트 고정 확인. 다크 OS(내 환경이 그랬음)에서 네이티브 컨트롤이 어둡게 뜨는 사고를 1줄로 막는다.
2. [S] 가격 표기 정직성: 엔 원문이 항상 먼저, 원화 환산은 "약 ₩N · 참고 환율 날짜" 보조로. 지역 평균/공식 사이트만 있는 값은 숫자로 환산하지 말고 "공식 사이트에서 확인"만. 환율 stale 태그는 이미 있음(fxOldTag) -> 비교표에도 같은 태그 보장. 추정치 표시 금지 거부권 준수.
3. [S] 죽은 코드 정리(ponytail): 모바일 이후 불필요해진 스택 규칙, 사용처 없는 ja.css류, 중복 `?v=` 상수, 비교창 도입으로 남은 옛 찜 전용 문구. `_removed/`로 이동 후 `node tools/security/check.mjs` 통과 확인. 번들러 도입은 REJECT(빌드 없는 구조가 유지비 0).
4. [M] 페이지당 렌더 수 제한: `content-visibility:auto`는 stack.css 1곳만 확인. 카드 20장 DOM은 가볍지만 서랍·비교·지도 3개가 겹치면 모바일 INP가 걱정. 전체 목록을 한 번에 DOM에 넣지 않는 현재 페이저 방식 유지, "더 보기" 무한 스크롤은 REJECT.
5. [S] 빈 상태/빈 결과 복구: 0건일 때 "마지막 조건 해제"에 더해 검색어 있을 때 "검색어 지우기" 버튼 1개, 비교창에서 찜 1개뿐이면 "하나 더 찜하세요" 안내(문구 C.need는 있음, 카드 쪽 버튼 비활성 사유도 aria-describedby로 연결).

## 4) 이 좌석이 반드시 막고 싶은 것
- 다크모드 신설, 시간 단위 환율 폴링, 번들러/프레임워크 도입, 지도 전체 보기: 모두 유지비 대비 이득 없음.
- 새 외부 호스트(이미지·폰트·스크립트)와 CSP 변경 동반 기능. 폰트는 오히려 줄일 것.
- CSS 레이어 한 겹 더 얹기(이미 13개 파일이 뒤가 앞을 덮는 구조). 새 규칙은 theme.css/stack.css에 합치고 새 파일 금지.
- 비교표/카드에서 값 없음을 "-"/0으로 바꾸거나 환율로 가격을 만들어 내는 것(거부권).
