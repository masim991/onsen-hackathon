# R3 기능 (find → compare → go book)

## 1) 결론
"찾기"는 동작하지만 "비교"는 기능 자체가 없고, "예약 이동"은 공식 링크까지만 신뢰할 수 있다. 가격이 있는 시설이 극소수라 정렬·예산 필터가 사실상 장식이다.

## 2) 문제 TOP 5
1. [치명] 비교 기능 부재. site.js에 compare/비교 기능 코드 없음(grep 결과 문구뿐). 찜(.fav)은 localStorage 목록 필터(#favToggle)일 뿐, 찜 2개 이상을 나란히 보는 화면이 없음. 히어로가 "한눈에 비교"라고 약속하는데(i18n.js eyebrow) 실제로는 카드 1개씩 서랍을 열어야 함 → 제품 목표의 중간 단계가 끊김.
2. [치명] 가격 데이터 희박. 가격 오름차순 정렬(전체 2,729곳) 1쪽에 가격 있는 카드 4장, 2쪽은 0장. 예산 슬라이더(#dayMax, 5,000~101,000엔)를 5,000엔으로 내려도 2,729→2,496(약 233곳만 걸러짐). 기본 목록(1,015곳) 첫 쪽 카드 20장 중 약 절반이 "가격 미공개". 정렬/예산이 비교 도구로 쓸 수 없음. (추측 금지 유지, 그래서 "가격 있는 곳 N곳" 같은 정직한 안내가 필요)
3. [높음] "사진·가격 있는 곳만 보기"(#richOnly)가 이름과 달리 가격 보장 안 함: 1,015곳 → 7곳, 첫 카드(료칸 이치노이)가 "가격 미공개". 이름과 결과 불일치, 7곳으로는 비교 불가.
4. [높음] 예약 이동 경로 불균등. 서랍(#detail)에 공식 사이트 링크는 샘플 5/5 있음. 그러나 Booking/Trip/자란/라쿠텐은 샘플(3쪽 5곳, 이름순 앞부분 10곳)에서 0건, 구로카와 이치노이에서만 4곳 확인. 링크가 날짜·인원 없는 상품 페이지 URL이라 "예약하러 간다" 흐름이 한 단계 부족(서랍 안내 "각 사이트에서 확인합니다"). 공식 링크가 목록 카드에는 없어 서랍을 열어야 이동 가능.
5. [중간] 희소 필터와 페이저. 체크박스 결과: 카드 결제 4곳, 주차 3곳, 송영 3곳, 1인 21곳, 객실 노천탕 12곳(전체 2,729 중) → 조합하면 0건이 쉽게 남. 페이저는 "이전 1 2 3 … 137 다음"뿐이라 중간 쪽 직접 이동 불가(60쪽 버튼 없음). 자연어/영어/일본어 검색은 하코네 72·箱根 71·hakone 67로 동작하나 "료칸 가격 저렴"은 0건(빈 상태 안내 미확인).

## 3) 제안 TOP 5
1. 비교 트레이: 찜 카드에 "비교" 체크(최대 4) → 하단 고정 바 → 표(요금, 당일 입욕, 노천/대절탕 수, 원천 온도, 확인일, 공식 링크). site.js 서랍 렌더 재사용, 값 없음은 "확인되지 않음" 그대로. 비용 L(최소형 M: 찜 목록 화면을 표로).
2. 가격 정직화: #richOnly 라벨을 "사진 있는 곳"과 "가격 있는 곳"으로 분리하고 각각 건수 표시. 정렬 select에 "가격 있는 N곳이 먼저" 안내 한 줄. stack-list.js/site.js 문구만. 비용 S.
3. 카드에 "공식 사이트" 아이콘 링크를 .side(.fav 옆)에 추가해 서랍 안 열고 이동. 목록 → 예약처 1클릭. 비용 S.
4. 페이저에 쪽 번호 점프(select 또는 입력) 또는 "더 보기" 병행. stack-list.js 페이저. 비용 S~M.
5. 희소 필터 옆에 건수 표시(이미 일부 있음: 노천탕 62)를 현재 조건 기준 "조합 시 N곳"으로 갱신하고 0건일 때 마지막 선택 조건 해제 버튼. site.js. 비용 M.

## 4) 하지 말아야 할 것
- 값이 없는 시설의 가격/예약 링크를 추정·템플릿으로 생성해 채우기(거부권 위반).
- 비교표에서 빈 값을 "-" 또는 0으로 바꾸기. "확인되지 않음" 유지.
- OTA URL에 날짜를 임의로 넣어 "예약 가능"처럼 보이게 하기, 제휴/외부 스크립트 추가.
- 정렬을 가격순 기본값으로 바꾸기(이름순 기본 정책 유지).
- 새 이미지 호스트나 지도 타일 추가(CSP/SECURITY.md 규칙).
