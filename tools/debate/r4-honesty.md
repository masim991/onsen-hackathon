# R4 좌석: 데이터 정직성·법무·보안
근거: r3-decisions, r3-photoless-sourcing(robots는 허락이 아님), final-decisions 거부권, tools/security/csp.txt. 라이브 사이트는 열지 않았고 코드·문서만 확인했다(법령·약관은 일반 지식이라 시행 전 재확인 필요, 법률 자문 아님).

## 1) 결론
- 허용 3종: (A) 공식 사이트 가격을 사람이 확인해 출처 URL·확인일과 함께 입력, (B) 예약 사이트는 "링크 이동"만, 가격은 공식 API/제휴 데이터가 있을 때만 "스냅샷"으로, (C) 지역 평균은 우리 확인 데이터의 집계 또는 정부 통계를 "참고값"으로 따로 표기.
- 금지: 예약 사이트 스크래핑, 추정·보간·AI 생성 가격, 평균을 시설 가격 칸에 넣기, 평균 대비 "저렴/비쌈" 판정, "최저가" 문구.
- 핵심 원칙: 가격은 값 + 종류(kind) + 단위 + 출처 + 확인일이 한 묶음. 하나라도 없으면 표시하지 않고 "가격 미공개 · 공식 사이트에서 확인"을 쓴다.
- CSP는 링크 이동만이면 변경 불필요. 외부 위젯·iframe·클라이언트 API 호출은 거부.

## 2) 판정표
| 안건 | 판정 | 한 줄 이유 |
|---|---|---|
| 공식 사이트 가격 수동 입력(1곳씩, 사람 검증) | ACCEPT | 가격은 사실 정보이고 출처·확인일을 붙이면 오인 소지 없음. 본문·사진 복제는 금지, 숫자만. |
| 공식 사이트 자동 추출(tracker) → 공개 | MODIFY | 후보로만 저장, 사람 승인 후 공개. final-decisions P12(가격 키워드 플래그 비공개)와 일치. 공식 사이트 robots 준수, 1초 간격. |
| Jalan/Rakuten/Ikyu/Booking/Agoda 스크래핑 | REJECT | 약관이 자동 수집을 금지, 가격은 날짜·인원·플랜별 변동이라 낡은 숫자가 곧 오표시. 부정접속·업무방해 분쟁 위험. |
| 예약 사이트 공식 API(예: 라쿠텐 트래블 웹서비스) | MODIFY | 약관 허용 범위·크레딧 표기·캐시 기간을 확인한 뒤 빌드 시점(tools/export-catalog)에만 호출. 키는 클라이언트 금지. 현재 제공 여부는 직접 확인. |
| 예약 사이트로 이동 링크 | ACCEPT | 검색 결과/시설 페이지 URL만. 새 호스트 허용 불필요. 제휴 링크면 "광고/PR" 표기(일본 스텔스마케팅 규제 2023.10 시행, 한국 표시광고법도 동일 취지). |
| 지역 평균(우리 데이터 집계) | MODIFY | n(표본 수) 최소 5곳, 종류·단위가 같은 값끼리만, 범위(최소~최대)와 함께 "참고값". 가격 필터·비교표 기본 계산에서 제외. |
| 지역 평균(관광청 등 정부 통계) | MODIFY | 출처·조사 연도 인용(PDL1.0 계열은 출처표기 필수). "숙박 지출 통계이며 이 시설 요금이 아님" 병기. |
| P2 가격 N곳/M곳 줄, 미공개 포함 기본 | ACCEPT | 구현 확인된 방향. 평균이 들어와도 "가격 확인 N곳" 수에는 절대 포함 금지. |
| 카드 "가격 미공개 · 공식 사이트에서 확인" | ACCEPT | 평균이 있어도 카드 가격 칸은 비운다. 평균은 서랍 하단 보조 줄에서만. |
| 비교 트레이 "확인되지 않음" | ACCEPT | 행 "가격 종류"를 추가해 공식/예약스냅샷/참고를 구분. |
| 추정 채우기, 공식 og:image 핫링크 | REJECT(유지) | 기존 거부권. 핫링크는 저작권·CSP 문제. |
| Commons 사진 파이프라인(사람 승인) | ACCEPT(보류 유지) | 라이선스·저작자 표기 필수, 자동 적용 금지. |

## 3) 신규 제안 TOP 5
1. [M] price_kind 4값 도입: official(공식 확인) / booking_snapshot(예약 사이트 스냅샷) / area_ref(지역 참고) / none. 표시 문구 ko/ja/en 고정:
   - official: "공식 사이트 기준 · 확인일 YYYY-MM-DD · 요금은 변동될 수 있음" (公式サイト掲載 / Per official site)
   - booking_snapshot: "예약 사이트 표시가 · 조회일 · 날짜·인원에 따라 다름" (OTA名 표기, 크레딧 포함)
   - area_ref: "참고: ○○지역 확인된 N곳 ¥a~¥b (중앙값 ¥c) · 이 시설 요금 아님"
   확인일이 90일 넘으면 "오래된 정보" 태그, 360일이면 가격 숨김.
2. [S] 단위 필수화: "1박 1인(식사 포함 여부)", "당일입욕 성인", "객실당" 중 하나를 값과 함께 저장. 단위 다른 값끼리 평균·정렬·필터 금지. 환산 원화에는 "약" + 환율 기준 시각, 엔 원문 병기(P10 유지).
3. [S] 예약 이동 버튼 규격: 외부 링크 아이콘 + "공식 사이트(外部サイト)" / "예약 사이트에서 확인", rel="noopener noreferrer"(제휴면 + sponsored), 사용자 검색어·찜 목록을 URL에 싣지 않음, 제휴면 푸터에 공개 고지 페이지 링크.
4. [M] 데이터 출처 장부: catalog에 price_source_url, price_checked_at, price_checked_by, price_kind 필수 필드와 tools/security/check.mjs 검증(필드 누락·http 링크·평균이 official로 표기되면 빌드 실패). 평균은 파생값이라 원본 필드에 저장하지 않고 빌드 시 계산.
5. [S] 구조화 데이터·SEO 방어: JSON-LD Offer/priceRange에는 official만 사용, area_ref·스냅샷은 넣지 않음. 메타 설명에 "최저 ¥○○" 같은 문구 금지. 사이트 푸터에 "가격은 참고용이며 최종 요금은 공식·예약 사이트에서 확인" 상시 노출.

## 4) 이 좌석이 반드시 막고 싶은 것
- 예약 사이트(Jalan·Rakuten·Ikyu·Booking·Agoda)를 스크래핑하거나 그 화면·이미지·리뷰를 복제하는 것. 약관 위반이고 공개 사이트라서 책임이 제품에 직접 온다.
- 평균·중앙값을 시설 가격처럼 카드·정렬·필터·비교표 기본 행에 넣는 것, 그리고 "평균보다 저렴/합리적" 같은 판정 문구(우량오인·오인 표시 소지).
- 클라이언트에서 예약 API/위젯 호출: API 키 노출, connect-src·script-src·frame-src 확대. 필요하면 빌드 시점 호출 + 결과를 정적 JSON으로. 새 호스트는 CSP 4곳(html meta, vercel.json, serve.json, csp.txt)과 SECURITY.md를 같이 고칠 때만.
- 확인일·출처 없는 숫자, 또는 숫자 없이 "대략 ¥○○ 안팎" 같은 서술형 추정. 값이 없으면 비워 두고 공식 링크를 앞세운다.
- 제휴 링크를 일반 링크처럼 보이게 하는 것(광고 표기 누락).
