# R3 보여지는 이미지 (visual/photo) 판정

## 1) 결론
히어로는 합격(1280w, fetchpriority=high, 375/1024 모두 선명)이지만, 1,015곳 중 사진은 7곳(0.7%)뿐이고 그 카드만 원본 해상도(최대 6000x3989)를 그대로 받아 목록이 "사진 한두 장 + 빈 칩 줄"로 보인다. 비교 도구로서는 이미지가 거의 기능하지 않는다.

## 2) 문제 TOP 5
1. [높음] 사진 커버리지: "사진·가격 있는 곳만" 클릭 → 7곳(.card 7개). 첫 페이지 20장 중 사진 카드 3장(가네요시 잇토안, 가메야 료칸, 가부토유온센). 근거: .card img 개수. 영향: 사용자가 사진으로 비교 불가, 사진 있는 카드는 높이 380~491px, 없는 카드는 107px로 그리드 리듬이 깨진다(한 줄에 키 4배 차이).
2. [높음] 카드 사진이 Wikimedia `commons.wikimedia.org/wiki/Special:FilePath/...` 원본. 실측 naturalWidth 6000x3989, 6007x3994, 5258x2941, 2560x1920를 343px 폭에 표시. loading=lazy지만 srcset/width/height 없음(img 7개 중 noWH 7), 일부 complete=false로 지연. 영향: 모바일 데이터 수 MB/장, 스크롤 시 빈 박스 후 점프(CLS), 느린 망에서 카드가 깨져 보임. 리다이렉트 때문에 캐시도 불리.
3. [중간] 크레딧 불균형: 히어로는 "사진: 노보리베쓰 온천 풍경. 作者 · CC BY-SA 3.0", 카드/드로어는 "Abasaa · 크기 조정 · 사진 원본 · Public domain"처럼 무엇을 찍은 사진인지 설명 없음. 알 수 없는 사람 이름 한 줄이 사진 아래 상시 노출 → 시각적 잡음. 영향: 신뢰감 낮고 12~13px 텍스트가 카드 하단을 차지.
4. [중간] 모바일(375) 딥링크 `#facility-official-yamashiro-hoshotei` 로드 시 스크린샷 2회에서 드로어 본문이 히어로 사진 위에 반투명으로 겹쳐 글자 판독 불가(드로어 computed bg는 불투명 z900이었으니 전환 중 렌더/히스토리 상태 가능성, 재현 확인 필요). 영향: 공유 링크로 처음 온 사용자의 첫 인상이 깨짐. 근거: cover-on drawer-open 클래스 동시 존재.
5. [낮음] alt: 히어로 alt="" (장식 처리, 크레딧 캡션이 대체), 지도 타일 4~10장 alt="". 카드 사진 alt는 시설명(OK). 영향: 히어로 의미 전달이 캡션에만 의존. 다국어 일관성은 ko/en 크레딧 문구 번역 확인됨(en: "resized · original"), 문제 없음.

## 3) 제안 TOP 5
1. 카드 이미지를 썸네일로: db 사진 URL을 `upload.wikimedia.org/.../thumb/.../640px-<file>`(hires.js hiUrl 방식 재사용, 이미 허용 호스트)으로 변환하고 srcset 640/960, `width=640 height=480`(또는 aspect-ratio:4/3) 지정. 파일: db-loader.js/site.js 카드 템플릿, style.css .card img. 비용 S~M. 6000px 원본 → 수십 KB.
2. 사진 카드/무사진 카드 높이 균형: 사진 비율 고정 4:3(aspect-ratio)+max-height 200px, 무사진 행은 합의된 84px 칩 행 유지(final-decisions P1) 대신 사진 카드도 가로형(좌 140px 썸네일 + 우 정보)로 통일하는 옵션 검토. 비용 M.
3. 크레딧 축소: 카드에서는 이미지 우하단 © 아이콘 + 호버/탭 시 전체 출처, 드로어에서만 전문 표기(라이선스 의무는 드로어 링크로 충족). `.card-credit` 숨김이 아니라 접기. 합의된 "출처 표기 유지" 위반 없이 가능. 비용 S.
4. 사진 없는 카드/드로어에 "사진 없음" 대신 지도 타일 대표 이미지는 쓰지 말고(정밀도 오인 금지) 지역 일러스트/아이콘 칩(P1) 유지, 사진 있는 곳 필터 라벨에 개수 "(7곳)" 표시. 비용 S.
5. 드로어 딥링크 겹침 재현·수정: 모바일 375에서 `?nointro#facility-...` 직접 진입 후 .cover/.detail 레이어 z-index와 cover-on 상태 확인, 드로어 열릴 때 커버를 visibility:hidden. 파일: cover.js/style.css. 비용 S.

## 4) 하지 말아야 할 것
- 사진 없는 카드를 임의 스톡/히어로 사진이나 지도 타일 이미지로 채우지 말 것(추정 금지, 정밀도 오인).
- 히어로 해상도를 낮추거나(1280w 미만) fetchpriority를 빼서 속도를 얻지 말 것.
- 새 이미지 호스트 추가 금지(upload.wikimedia.org는 hires.js가 이미 사용 중이므로 CSP 재확인만).
- 크레딧/라이선스 표기를 삭제하지 말 것(접기까지만).
- 사진 유무로 기본 정렬을 바꾸지 말 것(이름순 유지).
