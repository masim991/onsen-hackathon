# R3 불편한 점 (냉정한 비판)
측정: 로컬 5188, ko/ja/en, 375x812와 1440x900. 주의: 브라우저 창을 다른 보이스와 공유해서 뷰포트·언어·찜 수가 중간에 바뀜(찜 "1"은 내가 누른 게 아님). 시간값은 참고용.

## 1) 결론 한 줄
"비교하고 예약하러 가는" 목표를 데이터가 못 받쳐 준다: 2,729곳 중 숙박 요금 13곳(0.5%), 사진 324곳(12%), 소개문 120곳(4%)이고 비교 UI는 없다. 이 상태에서 카드·커버 연출을 더 다듬는 건 빈 그릇을 닦는 일이다.

## 2) 문제 TOP 5
1. [치명] 기본 화면이 "미확인" 벽. 기본(숙박, 가나다순) 1,015건 첫 페이지 8장 중 7장이 "요금·온천수 미확인", 사진 자리는 글자 "가" 타일. 가격 낮은 순 정렬을 눌러 보니 가격 있는 곳이 2곳뿐이고 3번째부터 다시 이름순 무가격. 실제로 정렬이 거짓말처럼 보인다. 영향: 비교 불가, 첫 방문자가 "빈 사이트"로 판단.
2. [치명] 비교 기능 없음. 코드에 "비교"는 안내 문구("시설을 서로 비교하기 위한 참고 자료")뿐. 찜(하트)만 있다. 영향: 서랍을 열고 닫으며 기억으로 비교해야 하고, 서랍은 빈 시설도 약 1,500자 안내문(6가지 확인, FAQ 3개, 같은 온천지 6곳)과 720px 폭 "사진 없음" 큰 상자를 띄운다. 실제 정보는 1줄.
3. [높음] 죽은 필터. 체크박스 카운트: 카드 결제 0, 송영 0, 주차장 0, 식사 없이 숙박 0, 노천탕 15, 대절탕 7, 객실 노천탕 2, 원천 방류 2. 0건 필터를 노출하는 것 자체가 불신. 온천지 select는 옵션 약 700개 한 줄 드롭다운, 같은 곳이 중복(구로카와/구로카와온천/구로카와 온천, 아칸코/아칸코 온천, 하코네/하코네 온천). 도도부현 순서도 북→남이 아님(홋카이도, 아키타, 아오모리, 이와테... 효고 뒤 와카야마, 교토, 오사카).
4. [높음] 무게와 모션. (a) 첫 로드 디코드 합계 약 3.0MB: 구글 폰트 69개 파일 1,065KB + CSS 383KB, 히어로 wikimedia 790KB, 로컬 JS/CSS 41개 798KB, 총 요청 약 60개. (b) 카드 사진이 247px 폭인데 원본 2560/6000/1024px(Kaneyoshi-Ittouan, Ryokan_Kameya, Kabutoyu)를 그대로 받음, 각 약 370ms. (c) 모바일 375: 고정 헤더 92px(화면 11%), 모바일에서 첫 결과 카드는 y=2268px(스크롤 2.8화면) 아래, 지역 타일 11개가 877px를 먼저 차지. 데스크톱도 첫 카드 y=1466px. (d) 커버가 position:fixed + scroll 연동 축소라 스크롤 시 헤더/커버가 계속 재배치됨. CLS는 낮음(0.024, 1.8초 사진 로드 시 1회)이라 이쪽은 큰 문제 아님.
5. [중간] 스택 행 스크롤 깨짐. 모바일에서 행(.stack-row)이 sticky + top 14px 단위로 쌓여 스크롤 중간(y≈4577)에 이전 행의 잘린 조각("가네요시 잇토안" 윗부분만 보임)이 새 카드 위로 겹침, 카드 사이 빈 간격이 불규칙. 모바일은 한 행 1장이라 쌓기 이득이 0이고 손해만 있음. 20장 한 페이지 높이 약 9,300px, 페이지 51개.
(그 외) 탭 타깃: 지역 칩 높이 40, 이전/다음 38x38, 일시정지 82x38, 서랍의 +/− 30px, Leaflet 링크 19~22px, "가기 전 확인할 것 자세히 보기" 21px, 유황천 같은 용어 링크 21px(44px 미만 30건). 메뉴에 "온천 찾기"가 두 번(nav에 2개). 모바일 메뉴 4번째부터 가로 스크롤로 잘림(받침 하트는 따로 있음). URL이 `?nointro=` 처럼 빈 값으로 남고, 검색하면 kind=stay가 kind=all로 바뀐다.
(언어) ja 브랜드 "温泉ひとめぐり"는 ko "온천 한눈에"(at a glance)와 뜻이 다름(ひとめぐり=한 바퀴 둘러보기). en 로마자 오류: "Okuoyaseukyo", "Niseko gosiki"(소문자/Goshiki), ko·en 커버에 일본어 "湯けむりの宿へ"가 번역 없이 남음. 인트로 브랜드는 "온유 溫遊 ONSEN JOURNEY"인데 사이트는 "온천 한눈에"로 서로 다름. 인트로/커버 카피 "공식 출처를 확인한 정보만"과 목록의 "미확인"이 충돌.

## 3) 제안 TOP 5
1. 기본 목록을 "정보 있는 곳 먼저"로(정렬 키: 요금/사진/공식사이트 유무 가산, 같은 점수 안에서는 이름순). final-decisions의 이름순 기본은 "같은 정보량 안에서"로 해석하거나 토글 "정보 많은 순" 추가. site.js 정렬 부분. 비용 M. 비추정 원칙 유지.
2. 카드 2~3장 체크 → 하단 고정 바 "비교(2)" → 나란히 표(요금, 노천탕, 온천수, 공식 사이트 링크). 비교 열에는 값 없는 항목은 "미확인"만. site.js + onchun.css. 비용 L. 최소안(M): 서랍에서 "찜 목록 표로 보기".
3. 0건 필터와 빈 서랍 정리: 0 카운트 체크박스 숨기기(또는 disabled+"0"→접기), 서랍에서 사진 없으면 큰 상자 대신 한 줄, FAQ 3개·"같은 온천지" 접기(details). 비용 S.
4. 모바일 스택 해제: `@media (max-width: 700px) .stack-row { position: static; }`, 지역 타일은 가로 한 줄 칩으로 접어 결과를 첫 화면 가까이. 비용 S. 카드 사진은 이미지 업스케일 URL을 폭 400px 썸네일로(commons `?width=400` 또는 thumb URL), Google Fonts는 사용 글리프만 쓰는 서브셋/로컬 폰트 후보 검토. 비용 M. (신규 이미지 호스트 금지 원칙 지킬 것)
5. 터치·문구 정리: 칩/페이저/일시정지 min-height 44, 서랍 +/− 44, "온천 찾기" 중복 제거, ja 브랜드를 "温泉ひと目で" 계열로 통일 또는 ko 직역 확정, en 로마자 표(i18n-data.js)와 오타 수정, 인트로 브랜드명 통일. 비용 S.

## 4) 하지 말아야 할 것
- 요금·소개를 추정해 빈칸을 채우지 말 것(0.5% 때문에 유혹이 큼). 해결은 수집/미확인 표기 쪽.
- 인트로·커버·스택 연출을 더 추가하지 말 것. 이미 모바일에서 손해(첫 카드 2.8화면 아래, 겹침 글리치).
- "미확인"을 숨기려고 건수만 줄여 보여주지 말 것(1,015→수십 곳으로 필터하면 지역 탐색이 막힘). 정렬로 올리고 숨기진 않는다.
- 비교 표에서 건강 효과·추천 문구를 넣지 말 것.
