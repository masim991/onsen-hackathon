# R4 이용자 대변인 (한국 여행자 + ja/en 방문자)

실측: localhost:5188 ko, 카드 20장 렌더, 필터 "사진 있는 곳 87 / 가격 있는 곳 19", 비교 트레이 실제 3곳 찜 후 열어봄(데스크톱 폭 확인, 375폭 모달 폭은 공유 브라우저 창 크기가 바뀌어 미검증). ja/en은 같은 셸 구조로 간주, 직접 화면 미확인.

## 1) 결론
"찾기 -> 비교 -> 공식 사이트" 뼈대는 이제 갖춰졌다(카드 공식 사이트 링크, 비교 모달에 공식 사이트 버튼 열마다 배치). 그러나 여행자가 "확신하고 예약 클릭"하려면 아직 세 가지가 약하다. (a) 비교표가 대부분 "확인되지 않음"이라 비교가 안 된다(내가 임의 3곳을 찜하니 가격 2칸, 온천수 1칸만 채워짐). (b) 가격에 기준(1박? 1인? 몇 명?)이 없어 ₩1,001,220 같은 값을 믿고 클릭할 수 없다. (c) 지금 값이 없는 곳(92%)은 "공식 사이트"가 유일한 출구인데 그 링크가 무엇을 해주는지(예약 가능? 요금표?) 알려주지 않는다. 최대 개선점은 "비교를 시작하기 전에 비교 가능한 곳을 알려주기".

## 3) 신규 제안 TOP 5
1. [M] 비교 진입 전 "비교 가능도" 안내: 트레이 열 때 "요금 확인 1/3, 온천수 1/3" 한 줄 요약 + 값 없는 칸이 많으면 "공식 사이트 3곳 열기"(순서대로 새 탭 열기) 대신 열별 버튼 강조. 찜 하트 누를 때 "요금 확인된 곳" 작은 배지(가격 있는 19곳)로 비교 후보 고르기 쉽게.
2. [S] 가격 기준 표기: 모든 가격에 "1박 기준 / 1인 / 요금표 기준일"(데이터에 있을 때만) 또는 "기준 미표시"를 붙이고, ₩1,001,220 같은 이상치(¥119,250)는 "최고가 객실 기준일 수 있음" 같은 근거 문구 없이 쓰지 말고 출처 표기. 환산 원화 옆 "현지에서는 엔화"는 이미 있음, 기준이 비면 비교 오독(싸다/비싸다)이 가장 큰 위험.
3. [S] 공식 사이트 버튼 문구 분화: "공식 사이트"만 있는 곳과 "예약 페이지/요금표 직접 링크"가 있는 곳을 구분(데이터 있을 때). 없으면 버튼 아래 "공식 사이트에서 요금·예약 확인" 한 줄. 한/일/영 모두 "예약은 공식 사이트에서"를 비교 모달 하단에 고정(현재 "요금과 운영 상태는 공식 사이트에서 다시 확인하세요"는 있음, 버튼에 연결되게 붙이기).
4. [M] 희소 결과 안내(활용성 문제 3 미해결 확인): 조건 조합이 0~7곳일 때 "대절탕 7곳 중 사가 2, 나가노 2..." 식 분포 한 줄 + "마지막 조건 해제" 외에 "조건 풀면 +N곳" 칩. 이용자는 "왜 적지?"를 모른다.
5. [S] ja/en 카피: 비교 모달 "확인되지 않음"을 ja "未確認", en "Not confirmed"로 통일(과도한 "Unknown/N/A" 금지), 찜 하트 문구를 "비교용 담기(Save to compare)"로 병기해 찜=비교 후보라는 연결을 알려줌. 일본인·영어권은 "favorite"를 즐겨찾기로 읽어 비교 기능을 못 찾는다("비교하기 (3)" 버튼이 하트와 멀리 떨어져 있음).

## 4) 이 좌석이 반드시 막고 싶은 것
- 가격에 기준·출처·기준일 없이 환산 원화만 크게 보여주기(오독 -> 예약 후 불만). 숫자 단위 없는 가격은 "약" 접두어로도 못 구한다.
- 비교표를 "값 없는 열"로 채워 놓고 정상 비교처럼 보이게 하는 것(빈 칸이 많을수록 "비교 불가, 공식 사이트에서 확인"으로 정직하게 바꿔야 함).
- 공식 사이트 링크를 가리는 중복(출처 링크와 같은 주소 두 번) 재도입, 그리고 새 창 링크에 "(새 창)" 안내 제거.
- 정렬을 몰래 가격순/정보순 기본값으로 바꾸는 것, 가격 없는 시설을 슬라이더로 조용히 숨기는 것.
