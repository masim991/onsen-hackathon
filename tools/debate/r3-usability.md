# R3 활용성 (과업 흐름) 판정

과업: "한 지역에서 대절탕(프라이빗 탕) 있는 숙소 3곳을 예산 안에서 골라 비교하고 예약으로 넘어가기". ko 데스크톱(1024폭) 실측, 모바일 375폭은 ko/en 구조 실측(스크린샷 대신 DOM 좌표), en 흐름 확인. ja는 같은 셸이라 동일 구조로 간주(미실측).

## 1) 결론 한 줄
탐색(필터/상세)까지는 되지만 "비교"는 기능 자체가 없고(비교 UI 0개, 찜은 필터일 뿐), 대절탕+예산 조합은 결과 7곳 중 가격이 있는 곳이 2곳이라 예산 필터가 사실상 무의미하며, 예약은 공식 사이트 링크 1개로만 이어진다.

## 2) 문제 TOP 5
1. [치명] 비교 기능 없음. 근거: DOM에서 compare 관련 요소 0개, 본문 "비교"는 문구뿐. 찜 버튼(#favToggle)은 누르면 칩에 "찜한 시설만"(en: Favorites only)이 붙는 필터로 동작할 뿐 나란히 보기 없음. 영향: 3곳을 비교하려면 상세 서랍을 3번 열고 닫으며 기억에 의존(클릭 약 3x2, 서랍 안 스크롤 필수).
2. [높음] 예산 필터가 가격 미확인 시설을 기본 포함. 근거: #inclUnp 기본 체크. 대절탕 7곳에서 예산 상한 ¥30,000으로 줄여도 "7곳을 찾았습니다" 그대로. 카드 7장 중 가격 있는 것은 메노유(약 ¥7,500)와 세이류소(약 ¥8,360) 2장뿐, 나머지 5장 "가격 미공개". 영향: 사용자는 슬라이더가 고장 난 것으로 오해. 체크박스가 슬라이더에서 멀어 원인을 못 찾음(오탐 신뢰 하락).
3. [높음] 지역x특수조건 결과가 0~1곳으로 쪼개짐. 근거: 대절탕 7곳이 전국 분산(사가 2, 나가노 2, 구마모토, 돗토리, 유타가와). "한 도도부현에서 3곳" 과업은 거의 불가능한데 이를 알려주는 문구가 없음("7곳을 찾았습니다"만). 영향: 조건을 하나씩 해제하며 헤매는 경로가 됨. 빈 결과/희소 결과 안내(어떤 조건을 풀면 몇 곳)가 필요.
4. [높음] 모바일 필터 동선. 근거: 375폭에서 필터가 접힌 details("조건으로 온천 찾기")이고 위치 y=1811 (약 2.2화면 스크롤 뒤), 열면 높이 2450px(약 3화면). 도도부현 select y=2500, 대절탕 체크 y=3036, 예산 슬라이더 y=4050. 필터는 sticky 아님(static). 영향: 조건 3개 거는 데 스크롤 약 5~6화면, 적용 결과(건수)는 화면 밖이라 변화를 못 봄. 전체 페이지 높이 12,254px.
5. [중간] 예약 이행이 약함. 근거: 상세 서랍(fixed)에 "공식 사이트(새 창)"와 "출처 페이지(새 창)"가 동일 URL(r-kujaku.com), 요금 "확인되지 않음", 당일 입욕 "확인되지 않음". 공식 링크는 서랍 상단 작은 텍스트 링크이며 예약 CTA 형태가 아님. 신뢰 면에서는 "확인되지 않음"/확인일/점검일 표기가 좋지만 사용자는 "예약 가능한가"를 알 수 없음. 가격 미공개 시설은 카드 하단에 "공식 사이트에서 확인"이라 말만 하고 카드에서 바로 공식 사이트로 가는 링크 없음(카드 클릭=서랍 열기 후 링크, 클릭 2회).

부가 관찰: 데스크톱 필터 영역에 모든 온천지(수백 개) 옵션 텍스트가 한 select에 들어 있어 정보 밀도가 과함. 조건 수(체크박스 약 25개)에 비해 "식사 없이 0, 카드 0, 송영 0, 주차장 0"처럼 0건 항목이 노출되어 노이즈. 데스크톱 필터는 sticky로 따라오나 목록 상단(y=1397)까지 히어로+지도로 약 1.8화면.

## 3) 제안 TOP 5
1. 비교 트레이(찜 기반): 카드의 찜 버튼 재사용, 하단 고정 바 "비교 (n/3)" -> 3열 표(요금, 대절탕/노천탕/객실 노천, 온천수, 확인일, 공식 사이트 버튼). 파일: site.js(찜 상태 읽기)+신규 compare 렌더러, stack.css. 값은 기존 RAW 필드만, 없으면 "확인되지 않음". 비용 L (표 하나만이면 M).
2. 예산 칩에 미확인 수를 붙임: 슬라이더 아래 "가격 있는 N곳 / 미확인 M곳 포함 중" 한 줄과 토글을 같은 줄에 이동. 파일: site.js 예산 출력부(#budgetOut 근처), #inclUnp 위치. 비용 S.
3. 희소/0건 결과 안내: 결과 요약줄(#resultSummary)에 "조건을 하나 풀면: 지역 해제 시 7곳 / 예산 해제 시 N곳" 해제 칩 제공. 0건 항목(체크박스 라벨 숫자 0)은 비활성 처리 또는 숨김. 비용 M.
4. 모바일 필터를 하단 시트 + 결과 건수 버튼("7곳 보기")으로 전환, 또는 최소한 #filters summary를 sticky 상단에 고정하고 건수를 늘 표시. 열었을 때 자주 쓰는 3개(지역, 대절탕/노천탕, 예산)를 최상단 배치. 파일: stack.css/style.css 모바일 분기, site.js. 비용 M.
5. 카드와 서랍에 예약 이행 버튼: 공식 URL이 있는 시설은 서랍 상단에 눈에 띄는 "공식 사이트에서 예약 확인(새 창)" 버튼 1개로 합치고 중복 "출처 페이지"는 URL이 다를 때만 표시. 카드에서도 보조 링크 노출. 외부 이동 직전 "요금은 공식 사이트가 우선" 한 줄. 비용 S.

## 4) 하지 말아야 할 것
- 가격 미공개를 추정/평균으로 채워 예산 필터를 "작동하는 것처럼" 보이게 하지 말 것(데이터 날조 금지).
- 비교표에서 건강 효능, "추천/최저가" 라벨을 달지 말 것(건강 주장/미확인 단정 금지). 정렬은 이름순 기본 유지.
- 예약 대행/내부 예약 폼처럼 보이는 UI 금지(사이트는 공식 사이트로 넘기는 역할). 새 외부 이미지 호스트나 위젯 추가 금지(CSP).
- 필터를 늘려 해결하지 말 것: 지금도 조건이 많아 모바일에서 3화면. 줄이고 순서를 바꾸는 쪽으로.
